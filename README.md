# FrameForge Studio

A cross-platform Electron desktop app for producing AI-generated video locally.
You bring your own provider API keys; the app has **no backend of its own** and
every artifact is rendered on your machine.

```
prompt + shot list ──► provider API (your key, direct)
                          │
                          ▼
                   clips on disk ──┐
                                   ├─► FFmpeg assembly ──► MP4 + poster
title cards (HyperFrames) ─────────┘                        │
                                                            └─► OfficeCLI deck / brief
```

## The four required integrations

| Requirement | How it is implemented | Where |
| --- | --- | --- |
| **Electron, cross-platform** | electron-vite (main / preload / renderer), electron-builder targets for NSIS, DMG and AppImage | `electron.vite.config.ts`, `src/main`, `src/renderer` |
| **HyperFrames UI** | Control surface uses HyperFrames Studio primitives (`Button`, `Input`, `Select`, `Toggle`, `Tabs`, `Tooltip`, `HyperframesLoader`, `cn`) and its compiled stylesheet; title cards are HyperFrames-style HTML/CSS compositions rendered by Chromium | `src/renderer/src/components/*`, `src/shared/composition.ts` |
| **OfficeCLI orchestration** | Storyboard `.docx` and delivery `.pptx` are generated by spawning the bundled `officecli` binary as a pipeline stage, with graceful skip when absent | `src/main/office/index.ts` |
| **FFmpeg local rendering** | Probe, normalise, xfade/concat, PNG-sequence encode, poster extraction — all via direct spawn (never a shell) | `src/main/ffmpeg/*` |
| **OS-native key vault** | `@napi-rs/keyring` → Windows Credential Manager / macOS Keychain / libsecret, falling back to Electron `safeStorage` (DPAPI/Keychain) | `src/main/vault.ts` |
| **No backend server** | All provider calls originate in the main process with the user's key; hosts are allowlisted and media URLs are SSRF-guarded | `src/main/providers/*` |

## Architecture

```
src/
  main/
    index.ts          app bootstrap, single-instance lock, ffcomp:// protocol, smoke harness
    security.ts       CSP, navigation guards, permission denial
    ipc.ts            zod-validated IPC handlers
    vault.ts          OS credential store + safeStorage fallback, metadata only on disk
    fsx.ts            atomic JSON writes (Windows rename-retry)
    providers/        runway · luma · fal · replicate · heygen · openai
    ffmpeg/           binary discovery, probe, normalise, concat, frame encode
    office/           OfficeCLI discovery + document generation
    render/cards.ts   offscreen Chromium capture, one PNG per frame
    jobs/             durable job store + staged runner
  preload/            contextBridge surface (dependency-free, sandbox-safe)
  renderer/           React 19 + Tailwind 4 + HyperFrames Studio UI
  shared/             zod contract, IPC constants, composition template
```

### Render pipeline

`validate → storyboard → generate → download → compose → render → export`

1. **validate** — FFmpeg/ffprobe present, provider key stored.
2. **storyboard** — OfficeCLI writes the brief from the same shot list.
3. **generate** — each shot is submitted and polled against the provider API.
4. **download** — clips stream to `workspace/projects/<job>/clips`.
5. **compose** — opening/closing cards are laid out in HTML, animated on a paused
   timeline, seeked per frame in an offscreen `BrowserWindow`, captured to PNG,
   then encoded with FFmpeg.
6. **render** — every segment is normalised to the project frame, joined with
   `xfade` or the concat demuxer, and copied to `workspace/output`.
7. **export** — poster frame, optional `.pptx` delivery deck, artifact records.

## Security model

- **Secrets never cross IPC.** The renderer can store, test and delete a key; it
  can never read one back. Provider calls happen in the main process.
- **Metadata only on disk.** `vault/keys.json` holds a truncated SHA-256
  fingerprint and the last four characters — never the secret.
- **Sandboxed renderer.** `contextIsolation: true`, `sandbox: true`,
  `nodeIntegration: false`, window-open denied, navigation restricted,
  permissions denied except clipboard writes.
- **CSP everywhere.** Strict `default-src 'none'` policy; composition documents
  are served from memory over a dedicated `ffcomp://` scheme with their own policy.
- **Host allowlist + SSRF guard.** API calls may only reach the six provider
  hosts; media downloads must be HTTPS and may not resolve to loopback,
  RFC1918, link-local, `.local` or `.internal` addresses.
- **No shell.** Every child process is spawned with an argument array.
- **Input validation.** All IPC payloads are re-parsed with zod in main.

## Documentation

`docs/GUIDE.md` is the source of truth for the user manual, and
`docs/FrameForge-Studio-Guide.pdf` is the rendered 13-page document with a cover,
a table of contents carrying real page numbers, and running footers.

```bash
pnpm docs:pdf      # Markdown -> print-styled HTML -> Chromium printToPDF (two passes)
pnpm docs:check    # pdf.js verification: sections present and in order, page count, encoding
```

The PDF is produced in two passes: the first lays the document out so each section's
page number can be read back with pdf.js, the second prints the same layout with a
populated table of contents. Only the Markdown is edited by hand.

## Requirements

- Node 22+ and pnpm 10+
- FFmpeg + ffprobe on `PATH` (or set `FRAMEFORGE_FFMPEG_DIR`)
- OfficeCLI (bundled as an npm dependency; document stages skip cleanly if missing)

## Quickstart

```bash
pnpm install
pnpm dev            # electron-vite dev server with HMR
```

Add provider keys in **Keys**, compose in **Studio**, press **Render locally**,
watch stages in **Jobs**. Output lands in
`%APPDATA%/frameforge-studio/workspace/output` (macOS/Linux: the equivalent
`userData` path).

## Verification

```bash
pnpm typecheck      # strict TS, zero any
pnpm test           # 41 tests: vault, providers, ffmpeg, pipeline, office, composition
pnpm build          # typecheck + electron-vite production build
pnpm smoke          # boots the app, checks bridge + vault round-trip, writes smoke.png
pnpm smoke:job      # full render through the real UI against a local mock provider
pnpm docs:pdf       # regenerate the manual PDF from docs/GUIDE.md
pnpm docs:check     # verify the PDF: all sections, page count, encoding
```

`smoke:job` generates a test clip with FFmpeg, serves it from
`scripts/mock-provider.mjs`, drives the actual app through a two-shot job and
verifies the exported MP4 with ffprobe. It requires no provider account.

The smoke run also round-trips a throwaway key through the real OS credential
store and removes it again, which proves persistence as well as IPC.

## Packaging

```bash
pnpm package        # unpacked app in release/
pnpm dist           # installers for the host platform
```

`@napi-rs/keyring` and `officecli` are unpacked from the asar archive
(`asarUnpack`) because both contain native executables.

## Known limits

- Provider request/response shapes track the vendors' public APIs and may drift;
  each adapter is isolated in `src/main/providers/` for exactly that reason.
- OfficeCLI runs in its anonymous-credit mode by default and can be switched to
  External Mode with `officecli config`; the app reports the detected mode.
- The app never transcodes on a server, so long jobs are bounded by local CPU.
- Installers are unsigned; signing/notarisation is left to the release pipeline.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `FRAMEFORGE_FFMPEG_DIR` | Directory containing `ffmpeg`/`ffprobe` |
| `FRAMEFORGE_OFFICECLI` | Explicit path to the `officecli` binary |
| `FRAMEFORGE_DEV_PROVIDER` + `FRAMEFORGE_DEV_BASE_URL` | Point one provider at a local gateway or mock (testing only) |
| `FRAMEFORGE_SMOKE`, `FRAMEFORGE_SMOKE_OUT`, `FRAMEFORGE_SMOKE_TAB`, `FRAMEFORGE_SMOKE_JOB` | Automated self-check harness |
